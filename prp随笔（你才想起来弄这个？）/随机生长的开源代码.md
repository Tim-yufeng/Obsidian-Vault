#### 1. `Model.cs` (算法骨架，最关键)

- ​**​角色​**​: 这是一个抽象基类，定义了 WFC 算法的核心逻辑和流程。它不关心具体的 tile 是什么，也不关心邻接规则如何定义，只提供一个通用的框架。
- ​**​WFC 主循环​**​:
    - `Observe()`: 这是 WFC 算法的关键一步。
        - ​**​选择最小熵节点​**​: 算法会遍历所有未确定的网格位置，找到“不确定性最小”的那个（即“熵最小”的节点）。熵越小，意味着该位置可选的 tile 种类越少，越容易确定。优先处理它有助于避免矛盾和提高效率。
        - ​**​按权重随机确定 tile​**​: 在选定的最小熵节点上，根据当前该位置所有​**​可容许​**​ tile 的权重（或概率），随机选择一个 tile 放置。一旦选定，该位置的 tile 就确定了。
    - `Ban()`: 当一个位置的 tile 被确定后，或者在 `Propagate()` 过程中发现某个 tile 在某个位置不再可能时，就会调用 `Ban()` 来禁用该位置的特定 tile。禁用后，需要更新该位置的局部熵和权重统计。
    - `Propagate()`: 这是 WFC 算法的另一个关键。当一个位置的 tile 确定或禁用后，这个约束会传播到其邻居。例如，如果位置 A 确定为 tile X，而 tile X 的邻接规则规定它不能与 tile Y 相邻，那么位置 B（A 的邻居）就不能再放置 tile Y。`Propagate()` 会递归地将这些约束传播出去，直到没有新的约束产生。
    - `Run(seed, limit)`: 这是整个生成过程的驱动函数。它会重复执行 `Observe()` 和 `Propagate()`，直到所有网格位置都被确定（成功完成），或者遇到无法解决的矛盾（失败）。
- ​**​维护的数据结构​**​:
    - `wave[i][t]`: 这是一个布尔数组，表示在网格位置 `i` 是否​**​允许​**​放置 `tile t`。`true` 表示允许，`false` 表示不允许。这是 WFC 算法的核心状态。
    - `propagator[d][t]`: 这是一个矩阵，表示在方向 `d` 上，`tile t` 允许哪些邻居 `tile`。这编码了邻接规则。
    - ​**​熵和权重统计数组​**​: 用于实现“最小熵优先”策略，并根据权重（或概率）进行随机选择。
- ​**​对应论文​**​: 这部分实现了论文中“每步选最小节点熵并更新可行集”的核心逻辑。

#### 2. `SimpleTiledModel.cs` (论文复现实际用的模型)

- ​**​角色​**​: 这是 `Model.cs` 的一个具体实现，专门用于处理基于“tile 集合”和“邻接规则”的 WFC 问题。它是论文中生成二维不规则材料微结构的核心。
- ​**​数据读取​**​:
    - 从 `samples/{name}/data.xml` 读取 tile 集合、对称性、邻接规则。
    - ​**​Tile 扩展​**​: 根据 `symmetry` 类型（如 `T/L/I/X/` 等），将原始定义的 tile 扩展成所有可能的旋转和镜像方向。例如，一个“T”形 tile 可能有4个旋转方向。
- ​**​关键改动​**​:
    - ​**​Tile 概率来源​**​: ​**​这里是关键！​**​ 它明确指出 `tile` 概率不是来自 `data.xml` 中固定的 `weight` 属性，而是来自传入的 `MargFreq`（即论文中的 `frequency hints`）。这意味着 `SimpleTiledModel` 在 `Observe()` 步骤中选择 `tile` 时，会使用 `Main.cs` 传入的动态 `frequency hints` 来计算概率。
- ​**​邻接规则构建​**​: 根据 `data.xml` 中 `<neighbor left="..." right="...">` 标签，构建一个 4 方向（上、下、左、右）的兼容矩阵 (`propagator`)。这个矩阵告诉算法，如果一个位置放置了 `tile A`，那么它在某个方向上的邻居可以放置哪些 `tile B`。
- ​**​输出​**​:
    - `Graphics()`: 生成最终的图像（PNG 文件），可视化生成的微结构。
    - `TextOutput()`: 输出每个网格位置选定的 `tile` 名称和朝向，以编码文本形式。

#### 3. `OverlappingModel.cs` (原版 WFC 的另一种模式)

- ​**​角色​**​: 这是 `Model.cs` 的另一个具体实现，代表了原版 WFC 算法的另一种模式，即“从图像中学习模式并生成新图像”。
- ​**​工作方式​**​: 它读取一个示例图像，从中提取 `N x N` 大小的“patch”（小块），将这些 patch 作为模式库。模式的频率来自这些样本的统计。然后，它使用这些 patch 的重叠一致性来构建邻接约束。
- ​**​与论文复现的关系​**​: 这个 `OverlappingModel` 在本次论文复现中​**​没有被使用​**​。`samples.xml` 文件只启用了 `simpletiled` 模式，所以 `overlapping` 只是仓库中保留的一个通用功能。

#### 4. `Main.cs` (批量生成驱动器)

- ​**​角色​**​: 这是整个程序的入口点和控制中心，负责驱动批量生成过程。
- ​**​设定参数​**​:
    - `Ntrials = 1000`: 设定了要采样的候选频率提示点的数量。
    - `Ndim = 4`: 设定了基本 tile 的种类数量（对应 `t/cross/line/corner` 四种）。
    - `setname = "Dense4"`: 指定了要使用的 tile 子集名称，这个名称会对应到 `data.xml` 中的 `<subset name="Dense4">`。
- ​**​生成频率提示 (`frequency hints`)​**​:
    - ​**​采样方法​**​: 使用 `-log(1-u)` 归一化方法来生成 Dirichlet 风格的采样点。这与论文补充材料中描述的生成均匀分布频率提示的方法一致。
    - ​**​“去拥挤筛选”​**​: 为了避免频率提示点过于集中，它使用一个最小欧氏距离阈值 `0.01` 进行筛选。只有当新的采样点与所有已接受的点之间的距离都大于 `0.01` 时，才接受这个点。这确保了生成的频率提示组合在多维空间中分布得比较均匀。
- ​**​批量生成循环​**​:
    - 对每个筛选后的频率组合：
        1. ​**​构造 `MargFreq`​**​: 将当前的频率组合封装成 `MargFreq` 对象，作为参数传递给 `SimpleTiledModel`。
        2. ​**​加载 `SimpleTiledModel`​**​: 根据 `samples.xml` 的配置，实例化 `SimpleTiledModel`。
        3. ​**​多次尝试运行​**​: 由于 WFC 算法可能因为矛盾而失败，程序会多次尝试运行 `SimpleTiledModel` 的 `Run()` 方法。
        4. ​**​输出结果​**​: 如果 `Run()` 成功，则输出生成的微结构图像（PNG 文件）和编码文本（txt 文件）。
- ​**​记录频率组合​**​: 最后，将所有筛选后的频率组合写入 `AutoMat/Dense4/Dense4 weights.txt` 文件。

#### 5. `Stuff.cs` (工具函数)

- ​**​角色​**​: 提供了一些通用的辅助函数，例如：
    - `Random(this double[] a, double r)`: 根据给定的概率分布 `a` 随机采样一个索引。
    - `Power()`: 幂计算。
    - `Get<T>()`: 从 XML 元素中读取指定类型的属性值。
    - `Elements()`: 根据标签筛选 XML 子元素。

#### 6. `samples.xml`

- ​**​角色​**​: 这是一个配置文件，定义了要运行的 WFC 任务。
- ​**​配置内容​**​:
    - `simpletiled, name="MatTiles"`: 指定使用 `SimpleTiledModel`，并引用 `samples/MatTiles/data.xml`。
    - `subset="Dense4"`: 告诉 `SimpleTiledModel` 只使用 `data.xml` 中 `Dense4` 子集定义的 tile。
    - `width=20, height=20`: 定义了生成网格的尺寸，与论文中 20x20 的网格统计体量一致。
    - `periodic=true`: 指定使用周期性边界条件，这在材料均匀化中很常见。
    - `screenshots=100`: 可能表示每个频率组合生成100个样本（与论文一致）。

#### 7. `samples/MatTiles/data.xml`

- ​**​角色​**​: 定义了“虚拟生长程序”的“基因库”，即基本构建块和它们之间的相互作用规则。
- ​**​`tiles` 列表​**​:
    - 定义了各种基本 `tile` 的名称（如 `t/cross/line/corner`），以及它们的 `symmetry` 类型。`symmetry` 类型（如 `T/L/I/X`）决定了 `SimpleTiledModel` 如何将这些基本 `tile` 扩展成所有可能的旋转和镜像方向。
- ​**​`neighbors` 列表​**​:
    - 包含大量 `<neighbor left="..." right="...">` 标签，这些标签定义了哪些 `tile` 可以作为另一个 `tile` 的邻居。这本质上就是论文中提到的“邻接规则”。
    - 注释掉的 `line 0` 与 `line 0`、`empty` 与 `empty` 示例，表明可以通过定义规则来主动禁止某些连接，以避免不希望的局部几何或拓扑结构。
- ​**​`subsets`​**​:
    - `Dense4`: 定义了一个 `tile` 子集，只包含 `t/cross/line/corner` 这四种 `tile`。`Main.cs` 中的 `setname="Dense4"` 就是引用这里。
    - 其他 `subset`（如 `Dense7/Full4/Grid`）提供了可扩展的配置，但在此次复现中未启用。
- ​**​一句话总结​**​: `data.xml` 就是论文所说的“基础构件 + 邻接规则”的代码化定义。

#### 8. `AutoMat/Dense4/Dense4 weights.txt`

- ​**​角色​**​: 这是一个输出文件，记录了所有被筛选后用于生成材料样本的 `frequency hints` 组合。
- ​**​内容​**​: 每行包含 `Ndim`（这里是4）个浮点数，它们代表了 `t/cross/line/corner` 这四种 `tile` 的频率提示，并且它们的和为 1。
- ​**​意义​**​: 文件中的每一行都对应着论文中“一组生长参数”，这些参数用于生成一批具有特定统计特性的材料样本。文件中的行数反映了经过“去拥挤筛选”后实际使用的频率组合数量。

### C# 文件如何形成一个工作流，传递参数信息？

整个工作流可以概括为：

1. ​**​`Main.cs` 启动​**​: `Main.cs` 作为程序的入口，首先根据预设参数（`Ntrials`, `Ndim`, `setname`）和论文中描述的采样方法，生成一系列​**​频率提示 (`frequency hints`) 组合​**​。
2. ​**​`Main.cs` 实例化 `SimpleTiledModel`​**​: 对于每个生成的频率提示组合，`Main.cs` 会：
    - 将当前的频率提示组合封装成 `MargFreq` 对象。
    - 读取 `samples.xml` 来获取任务配置（例如，使用 `MatTiles` 的 `Dense4` 子集，网格大小 20x20，周期性边界）。
    - 根据 `samples.xml` 的指示，实例化 `SimpleTiledModel`。在实例化时，`SimpleTiledModel` 会读取 `samples/MatTiles/data.xml` 来获取具体的 `tile` 定义、对称性信息和邻接规则。​**​关键在于，`Main.cs` 会将当前的 `MargFreq`（频率提示）作为参数传递给 `SimpleTiledModel`。​**​
3. ​**​`SimpleTiledModel` 执行 WFC 算法​**​:
    - `SimpleTiledModel` 继承自 `Model.cs`，因此它会调用 `Model.cs` 中定义的 `Run()` 方法来执行 WFC 主循环。
    - 在 `Observe()` 步骤中，`SimpleTiledModel` 会使用​**​传入的 `MargFreq`（频率提示）​**​来计算每个可容许 `tile` 的选择概率，而不是 `data.xml` 中可能存在的固定 `weight`。
    - 在 `Propagate()` 步骤中，`SimpleTiledModel` 会利用从 `data.xml` 构建的 `propagator`（邻接规则）来传播约束。
4. ​**​`SimpleTiledModel` 输出结果​**​: 如果 WFC 算法成功生成了微结构，`SimpleTiledModel` 会调用其 `Graphics()` 方法生成 PNG 图像，并调用 `TextOutput()` 方法生成编码文本文件。
5. ​**​`Main.cs` 记录​**​: `Main.cs` 会将所有成功使用的频率提示组合记录到 `AutoMat/Dense4/Dense4 weights.txt` 文件中。

### 最终得到什么？

通过这个工作流，最终会得到：

1. ​**​大量的微结构样本​**​: 对于 `Dense4` 这个 `tile` 子集，程序会生成大量不同的二维不规则微结构图像（PNG 文件），每个图像都对应一个特定的频率提示组合。
2. ​**​微结构的编码文本​**​: 对应的文本文件记录了每个网格位置上所选 `tile` 的类型和朝向，这对于后续的力学性能分析非常重要。
3. ​**​频率提示数据库​**​: `AutoMat/Dense4/Dense4 weights.txt` 文件记录了所有用于生成这些微结构的频率提示组合。这个文件是连接频率提示（输入）和材料性能（输出）的关键桥梁。
