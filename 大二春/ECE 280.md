# Developing and Compiling Programs on Linux

C++语言变成计算机能读懂的机器语言，经历了 编译（Compiling）- Linker 两步

![[Pasted image 20260306141954.png]]

**C++ 编译与链接的底层逻辑**

**核心概念**：平时最常用的“一键编译”命令，实际上在幕后是由**编译（Compile)** 和 **链接（Link）** 两个独立的步骤组成的。

平时输入的一键编译命令：
`g++ -o program source.cpp`

在底层，它**完全等价于**系统连续执行了以下两步：
1. `g++ -c source.cpp`  *(编译阶段)*
2. `g++ -o program source.o` *(链接阶段)*

**为什么 `g++ source.cpp -o program` 和 `g++ -o program source.cpp` 完全等价？**

* **`-o` 的唯一作用**：在 `g++` 命令中，`-o`（output）是一个选项参数，它的唯一规则就是——**紧跟在 `-o` 后面的那个字符串，就是你指定的输出文件名**。
* **顺序自由**：至于输入文件（`source.cpp`）是放在最前面还是最后面，编译器都能自动识别出它是需要被处理的源文件。
* 只要你保证 `-o` 后面紧紧挨着的是你想生成的名字（即 `program`），这几个模块在命令中的先后顺序是随意的。

![[Pasted image 20260307105724.png]]

.h 文件不需要包含在编译命令中，因为他们已经被包含在.cpp 的include中了

## Header Guard（为什么会产生“多重包含” (Multiple Inclusions)）

在 C++ 中，`#include "xxx.h"` 的本质非常简单粗暴：**预处理器会直接把 `xxx.h` 文件里的所有文本内容，原封不动地复制粘贴到 `#include` 所在的位置**。

随着项目变大，头文件经常需要包含其他头文件（例如 `drawing.h` 同时包含了 `point.h` 和 `line.h`，而 `line.h` 内部可能又包含了一次 `point.h`）。
* **后果**：在最终编译源文件时，同一个头文件（如 `point.h`）的代码会被复制粘贴多次。
* **报错**：编译器会抱怨“类或函数被多次重复定义 (multiple definitions)”。

---

为了解决重复复制粘贴的问题，C++ 引入了 **Header Guard（头文件保护符）**。

它依靠三个预处理指令工作：`#ifndef` (if not defined), `#define`, `#endif`。
* **第一次引入时**：条件变量（如 `ADD_H`）还未定义，所以通过检查，执行内容，并立刻 `#define ADD_H` 将其标记为已定义。
* **第二次引入时**：因为 `ADD_H` 已经被定义过了，`#ifndef` 检查失败，中间的所有代码会被直接忽略。
* **结论**：它保证了头文件里的内容在一次编译过程中**绝对只被看见一次**。

 **什么时候需要写 Header Guard？**
**答案是：几乎 100% 的时候！** 只要你创建了一个新的 `.h` 文件，第一件事就应该是写上 Header Guard（或者使用现代编译器支持的 `#pragma once`，作用相同）。这是 C++ 开发的铁律。

### 3. "One More Thing"：普通函数 vs. 类的区别
 情况 A：普通函数 (如 `add()`) —— 可以不引入
* 幻灯片指出，在定义像 `add` 这样的简单函数时，`add.cpp` 里面**不需要** `#include "add.h"`。
* **为什么？** 因为编译器在编译 `add.cpp` 时，看到 `int add(int a, int b) { return a+b; }` 就能直接生成机器码了，它不需要知道别的地方是怎么声明这个函数的。
* *(注：虽然语法上不需要，但实际工程中强烈建议引入，因为这样编译器可以帮你检查 `.cpp` 中的实现和 `.h` 中的声明参数是否一致。)*

 情况 B：类 (Class) —— 必须引入
* 幻灯片强调：**但是，在定义类时，你必须在对应的 `.cpp` 文件中引入 `.h` 文件**。
* **为什么？** 因为类的方法在 `.cpp` 中是这样写的：`void MyClass::doSomething() { ... }`。
  当编译器看到 `MyClass::` 时，它会问：“`MyClass` 是个什么东西？它占多大内存？它到底有没有 `doSomething` 这个成员？” 
  这些关键信息**全都在 `.h` 文件里的类声明中**。如果不 `#include` 进来，编译器完全不认识 `MyClass`，直接报错罢工。

### -I 用法
简单来说，就是在 .cpp 文件中 include 的 .h 文件，如果不在当前目录下，而是在别的目录，通过 -I 能帮助编译器找到他们

假设目录结构如下：

```text
my_project/
├── src/
│   └── main.cpp      (里面写了 #include "math_tools.h")
└── include/
    └── math_tools.h
```
.h 文件在 include/ 中，那么：
`g++ -o program main.cpp`
是不行滴，编译器找不到 math_tools.h 会报错，需要：
`g++ -o program main.cpp -I./include`
或者
`g++ -o program main.cpp -I include`
或者没有中间空格

### Makefile

![[Pasted image 20260307222805.png]]


Makefile 的基本格式是：
```
Target: Dependency
<Tab> Command
```
其中 Dependency 是本条命令执行的先修（？）条件/依赖文件，该命令的成功执行需要依赖文件已存在

注意：命令前必须是一个 `Tab` 缩进，绝不能是空格！

2. 核心运行逻辑：按需编译

依赖图 (Dependency Graph)：Makefile 会自动把你的文件串成一个树状图（比如 run_add 依赖 .o，.o 依赖 .cpp）。

触发条件 (核心重点)：一条命令什么时候会被执行？当“依赖文件”的修改时间比“目标文件”更新时 (When dependency is more recent than target)。这就实现了“谁改了就只重新编译谁”，极大地节省了大型项目的编译时间。

3. 如何使用

文件名：必须命名为 Makefile (注意首字母大写)。

终端执行：

输入 make：默认执行文件里的第一个目标 (First target，通常命名为 all)。

输入 `make <target>`：执行指定的目标。

4. 常用技巧：伪目标 (Dummy target)

通常会写一个 clean 目标用来清理编译产生的中间文件（如 rm -f run_add .o）。

它是一个“伪目标”：没有依赖项 (It has no dependency)，所以输入 make clean 每次都会强制执行清理命令。

基本思路（结合p2）：
Logic Execution Framework
When approaching a specific function, apply this framework sequentially:

Step 1: Identify the minimal unit. Ask: "What is the correct output if the input pointer is nullptr?"

Step 2: Trust the recursion. Ask: "If I call this function on node->next (or node->left/node->right), assuming it perfectly returns the correct result for the remainder of the structure, what must I do with the current node to complete the answer?"

Step 3: Determine the return type and allocation. Ask: "Does this function mandate modifying an existing structure, returning a computed value, or allocating entirely new memory?" If allocating a new structure based on a condition (like the filter functions), the allocation logic acts as the synthesis step.

# Recursion; Function Pointers;
### 1. **定义方式**
函数指针的定义需要指明它所指向的函数的返回类型和参数类型。例如：
```cpp
int (*foo)(int, int);
```
- `foo` 是一个指针
- 它指向一个函数
- 该函数接受两个 `int` 参数
- 并返回一个 `int`

### 2. **赋值与调用**
可以将一个符合类型签名的函数赋值给函数指针：
```cpp
foo = min;   // min 是一个函数
```
之后可以通过指针调用该函数：
```cpp
foo(3, 5);   // 调用 min(3, 5)
```

注意：编译器允许直接使用函数名赋值和调用，无需显式取地址（`&`）或解引用（`*`）。

### 3. **用途**
函数指针的主要优势在于提高代码的**通用性和复用性**。例如：
- 可以用同一个递归函数 `compare_help` 配合不同的比较函数（如 `min` 或 `max`）来实现查找列表中的最小值或最大值。
- 避免重复编写几乎相同的代码，提高代码的**可维护性**和**可读性**。

### 4. **对比普通指针**
- 普通变量指针需要取地址（`&`）和解引用（`*`）来操作。
- 函数指针在使用时则更加简洁，可以直接赋值和调用。

总结：**函数指针是一种让函数成为“一等公民”的机制，允许将函数作为参数传递，从而实现更灵活、更模块化的程序设计。**

## 函数调用机制与调用栈 (Function Call Mechanism & Call Stacks)


### 2. 函数调用的底层步骤 (The 6 Steps)
**当程序调用一个函数时，系统会按以下逻辑执行：**
1.  **评估参数**：计算实参 (Actual Arguments) 的值（计算顺序不确定）。
2.  **创建激活记录 (Activation Record / Stack Frame)**：在内存中开辟空间，用于存放函数的**形参 (Formal Parameters)** 和**局部变量**。
3.  **拷贝数值**：将实参的值拷贝到形参的存储空间中。
4.  **执行函数**：在局部作用域内执行代码。
5.  **返回结果**：用函数的返回值替换掉原本的调用表达式。
6.  **销毁记录**：回收该激活记录所占用的内存。

---

### 3. 调用栈 (Call Stack) 的运作原理
* **数据结构**：**后进先出 (LIFO)**。
    * **形象比喻**：就像食堂里叠放的一叠盘子。洗好的盘子放在最上面，拿盘子时也从最上面开始拿。
* **压栈 (Push)**：函数 $f()$ 被调用时，其激活记录被添加到栈顶。
* **出栈 (Pop)**：函数 $f()$ 执行完毕返回时，其记录从栈顶移除。
* **特性**：
    * **嵌套调用**：被调用的函数必须先返回并销毁记录，主调函数才能继续执行并最后返回。
    * **内存方向**：在实际内存中，栈通常是**向地址减小的方向生长**的（即“向下”生长）。

![[Pasted image 20260324161642.png]]

---

### 4. 内存隔离与指针传递
* **作用域隔离**：
    * 即使两个函数都有同名变量（如 `x`），它们也位于内存中不同的激活记录里，彼此互不干扰。
    * **值传递**只是将数值拷贝过去，函数无法直接看到对方的内部变量。
* **指针的特殊性**：
    * 当通过指针传递参数时，形参存储的是实参的**内存地址**。
    * **逻辑关系**：虽然激活记录是独立的，但指针变量（如 `int *x`）指向了主调函数中的变量地址，从而实现了“跨函数”修改数据。

---

### 5. 递归与栈 (Recursion on Stack)
* **压栈逻辑**：每进行一层递归调用，系统就会创建一个新的激活记录。
* **返回地址 (RA)**：每个激活记录都会记录一个**返回地址 (Return Address)**，告诉系统当该层函数执行完后，应该跳回到代码的哪一行继续执行。
* **易错点：栈溢出**：如果递归深度过大或没有基准情况，激活记录会填满整个栈空间。

![[Pasted image 20260324163640.png]]
---
### 重点总结与易错点标记
* **形参与实参**：形参是局部变量，函数退出后即消失。修改非指针形参**不会**影响实参。
* **返回顺序**：最后调用的函数永远是最先返回的。
* **变量可见性**：一个函数**绝对无法**直接访问另一个函数的局部变量，除非通过指针。
* **函数指针声明**：注意 `(*foo)` 的括号不能省，否则 `int *foo()` 会被解释为一个返回指针的函数。
* **递归效率**：
    * 递归代码通常简洁，但每层调用都有开销（创建/销毁记录）。
    * 可以通过逻辑优化（如 Fibonacci 序列的迭代实现）减少不必要的重复计算。

## 枚举、命令行参数与 I/O 流笔记

### 1. 枚举类型 (Enumeration / enum)
* **核心用途**：用于**对数据进行分类**。相比于使用 `const int` 手动编码（如 0 代表梅花，1 代表方块），`enum` 提供了一种更安全、更具读性的新类型。
* **语法定义**：
    ```cpp
    enum Suit_t { CLUBS, DIAMONDS, HEARTS, SPADES };
    Suit_t mySuit = DIAMONDS;
    ```
* **优势**：
    * **消除 REQUIRES 子句**：如果函数参数是 `int`，需要说明“必须在 0-3 之间”；使用 `Suit_t` 则在类型层面限制了取值范围。
    * **数值映射**：默认从 0 开始递增（0, 1, 2...）。可以配合字符串数组快速输出名称：`cout << suitname[mySuit];`。
* **自定义数值**：
    * 可以手动指定：`enum COLOR { red = -1, blue = 1, yellow = -2 };`。
    * ==若部分指定，未指定的项会在前一项基础上 +1==。
* **易错点**：**作用域冲突**。==同一个作用域下的两个不同 `enum` 不能包含同名的枚举常量==（如两个 enum 都定义了 `yellow` 会报错）。

---

### 2. 命令行参数 (Passing Arguments to Program)
* **基本概念**：程序可以像函数一样接收外部输入的参数，如 `diff file1 file2`。
* **main 函数改造**：
    * ==`int main(int argc, char *argv[])`==
    * **argc (Argument Count)**：整型，代表参数的总个数。
    * **argv (Argument Vector)**：字符指针数组（C-风格字符串数组），“==An array of pointers of char type==”
* **内存布局**：
    * `argv[0]`：始终是**程序名**（可能包含路径如 `./sumIt`）。
    * `argv[1]` 到 `argv[argc-1]`：才是用户输入的实际参数。
* **类型转换**：命令行传入的全部是字符串。若需转为整数，需 `#include <cstdlib>` 并使用 **`atoi(argv[i])`** 函数。

### 3. I/O 流 (I/O Streams)
* **流模型**：将输入输出视为**数据的序列**。像一根水管，数据从一端进入，另一端流出。
* **特性**：C++ 中的流是**单向的**。若需对同一文件进行读写，必须建立两个流。
* **常见流对象**：
    * **cout**：标准输出流（屏幕）。使用插入运算符 `<<`。
    * **cin**：标准输入流（键盘）。
    * **cerr**：标准错误流。默认也是屏幕，但**不带缓冲**，用于即时输出错误信息。

#### **格式控制与重定向**
* **setw(n)**：设置字段宽度。需 `#include <iomanip>`。它只影响**紧随其后**的**一个**输出项，默认**右对齐**并补空格。
	```cpp
	#include <iostream>
	#include <iomanip> // 必须包含此头文件
	using namespace std;
	int main() {
	    // setw(n) 设置字段宽度为 n，默认右对齐
	    cout << setw(6) << 42 << setw(6) << 1024 << endl;
	    return 0;
	}
	/* 预期输出（下划线代表空格）：
	____42__1024 
	*/
	```
* **重定向**：在 Linux 终端使用 `./program > filename` 可以将 `cout` 的输出从屏幕转到文件。

#### ==**缓冲机制 (Buffering)**==
* **原理**：为了效率，`cout` 输出的内容会先存放在内存的“缓冲区”中，而不是立即刷到屏幕。
* **刷新触发时机**：
    1.  插入换行符：**`endl`** 或 **`\n`**。
    2.  显式调用 **`flush`**。
    3.  缓冲区满了。
    4.  程序尝试从 `cin` 读取数据（自动刷新输出缓冲以便用户看提示）。
    5.  程序正常退出。
* **对比**：**`cerr` 是不带缓冲的**，确保错误发生时信息能立刻显示，即使程序意外崩溃。

### 4. 易错总结
* **数组越界**：访问 `argv` 时务必确保下标 `< argc`。
* **atoi 局限**：`atoi` 只能处理整数。如果是浮点数列表求和，应寻找类似 `atof` 的函数。
* **缓冲丢失**：如果程序非正常崩溃（如段错误），缓冲区内还未刷新的 `cout` 内容可能会丢失，导致调试时看不到最后的日志。此时应改用 `cerr`。

## I/O Streams

### 1. I/O 流核心模型
 **单向性 (Unidirectional)**：C++ 中的流是单向的。如果需要对同一个文件进行读和写，必须分别建立两个流对象。
* **数据分类**：
    * **字符流 (Character)**：用于键盘/屏幕交互、读写文本文件，易于调试。
    * **二进制流 (Binary)**：存储效率高，但不易直接阅读和调试。

---

### 2. 标准输出流 (cout & cerr)
* **插入运算符 `<<`**：自动将各种标准数据类型转换为字符序列。
* **格式控制**：使用 `setw(n)` 设置字段宽度（需包含 `<iomanip>`），默认**右对齐**并补空格。
* **重定向**：在 Linux 环境下，可以使用 `./prog > foo` 将 `cout` 的输出从屏幕转向文件。
* **cerr (标准错误流)**：
    * 专门用于输出错误信息。
    * **核心区别**：`cout` 是**有缓冲的 (Buffered)**，而 `cerr` **没有缓冲**，确保程序崩溃前错误信息能即时显示。

---

### 3. 标准输入流 (cin)
* **提取运算符 `>>`**：从输入流中提取数据，遇到**空白字符**（空格、制表符、换行）会停止。
* **getline(cin, str)**：读取整行，包括空格，直到遇到换行符为止。换行符会被读取并丢弃。
* **cin.get(ch)**：读取**单个**字符，包括空格和换行符。常用于处理 `>>` 留下的残留空格。
* **输入缓冲**：输入的字符先存入缓冲区，直到按下 **Enter** 键，程序才开始批量读取。这允许用户在确认前通过退格键修正错误。
* **失败状态**：如果提取的数据类型不匹配（例如期望 `int` 却输入了 `abc`），流会进入 **Failed State**。此时：
    * 可以使用 `if(cin)` 或 `while(cin)` 检查流是否健康。
    * 一旦失败，流将拒绝执行后续的所有提取操作。

---

### 4. 文件流 (File Streams)
* **头文件**：`#include <fstream>`。
* **对象声明**：`ifstream`（输入）、`ofstream`（输出）。
* **文件操作步骤**：
    1.  **打开 (Open)**：`iFile.open("filename")`。在 C++98 中必须传 C 风格字符串（`.c_str()`），C++11 及以后支持 C++ `string`。
    2.  **读写**：用法与 `cin`/`cout` 完全一致。
    3.  **关闭 (Close)**：`iFile.close()`。
* **关闭的重要性**：减少文件损坏风险；确保数据从缓冲区完全写入磁盘；以便后续程序重新读取该文件。
* **安全读取技巧**：
    * 错误示例：`while(iFile) { getline(...); }`。这会导致最后一行多读一次空行。
    * 正确示例：**`while(getline(iFile, line))`**。将读取操作作为循环条件，利用其返回值判断是否到达文件末尾。

---

### 5. 字符串流 (String Streams)
* **头文件**：`#include <sstream>`。
* **用途**：实现字符串与其他数据类型的**内存中转换**。
* **istringstream (输入)**：从字符串中提取数据。
    * 例子：将一行包含 "42 3.14" 的字符串拆分为一个 `int` 和一个 `double`。
* **ostringstream (输出)**：将数据格式化写入字符串。
    * 用法：通过 `<<` 插入数据，最后调用 **`.str()`** 获取最终拼接成的字符串。
具体用法见：[[stringstream]]

### 易错点与避坑指南
* **残留字符**：`cin >> val;` 之后如果立刻接 `getline()`，会读到 `val` 后面的换行符导致结果为空。此时需先用 `cin.get()` 消耗掉换行符。
* ** Failed State 陷阱**：一旦文件打开失败或输入格式错误，流对象会一直处于 False 状态。在重新使用前，通常需要手动重置（尽管本课件未深入此点）。
* **缓冲延迟**：调试程序时，如果 `cout` 的内容没出来，可能只是还待在缓冲区里。可以尝试添加 `endl` 或 `flush` 强制刷新。
