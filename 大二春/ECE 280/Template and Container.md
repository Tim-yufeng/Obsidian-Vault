### 1. 指针容器的动机
在之前我们已经看到了，通过 Template 的运用，我们可以在链表这个容器里面盛放各种数据类型：int, double, char ...，但是这些都是很小的数据类型，如果是一个 bigThing 呢？

![[Pasted image 20260417172246.png]]

* **内存效率**：如果容器存储的是大型对象（如包含数千个元素的矩阵），按值存储（Container of Objects）在插入、删除或拷贝时会产生巨大的开销。
* **共享对象**：多个容器可以同时指向同一个对象，而不需要为每个容器都复制一份副本。
* **多态支持**：这是最核心的动力。只有存储**基类指针**，容器才能在运行时同时容纳各种不同的派生类对象。

---

### 2. 基本定义与语法
* **定义形式**：通常将模板参数 `T` 指定为指针类型。
    * 例如：`List<Object*> mylist;`
* **节点结构变化**：容器内部的 `node` 现在存储的是一个地址。
    * `node->value` 是一个 `Object*` 类型。
![[Pasted image 20260417172306.png]]


---
存储指针后，容器里放的是地址，不是对象本身。这会导致两类严重 bug：

1. **悬空指针**：对象已经被删除了，但容器里还留着它的地址，再用就崩溃。
    
2. **内存泄漏**：容器销毁了，但对象没被删除，变成孤儿，再也找不到了。

为了解决这两个问题，课件提出了 **三个使用规则 + 一个不变式**：

### 规则 1：At‑most‑once invariant（最多链接一次）

> 任何对象最多只能被一个容器通过指针链接。

也就是说，你不能把同一个对象的指针插入到两个不同的容器里。否则两个容器都以为自己“拥有”这个对象，删除时就会出问题（比如重复删除，或者忘记删除）。

---

### 规则 2：Existence（存在规则）

> 插入容器的指针必须指向一个**动态分配**的对象（`new` 出来的），不能是局部变量的地址。

```cpp
BigThing b;          // 局部对象，函数结束就销毁
l.insert(&b);        // ❌ 错误

BigThing* pb = new BigThing;
l.insert(pb);        // ✅ 正确
```

---
### 规则 3：Ownership（所有权规则）

> 一旦指针被插入，该对象就归容器所有。之后只能通过容器的方法来修改它。

为什么？因为如果你直接拿到指针在外面乱改，可能会破坏容器内部的某些约束（比如一个“正整数容器”里被改成了负数）。

---
### 规则 4：Conservation（守恒规则）

> 当你从容器中 `remove` 一个指针后，要么马上把它插入另一个容器，要么就 `delete` 掉它。

不能既不删也不存，那样对象就泄漏了。

### Destructor 
为了避免出现容器被析构函数销毁，但是节点里面地址指向的对象还在的问题，我们采用以下做法：

```cpp
template <class T>
T* List<T>::remove() {    // 我们熟悉的链表 remove 函数
	if (isEmpty()) {
	listIsEmpty e;
	throw e;
	}
	node *victim = first;
	T* result = victim->value;
	first = victim->next;
	delete victim;
	return result;
}

template <class T>
List<T>::~List() {     // 析构函数
	while (!isEmpty()) {
		T *op = remove();    // 这里我们利用 remove 返回的地址，
		delete op;           // 销毁了其指向的物体
	}
}
```

### Constructor

构造函数要小心浅拷贝的发生，如果把链表值代表的指针拷贝了过去，那就违反 “At‑most‑once invariant” 了

正确的拷贝实现：
```cpp
template <class T>
void List<T>::copyList(node *list) {
	if (!list) return;
	copyList(list->next);
	T *o = new T(*List->value);
	insert(o);
}
```
关键在 `T *o = new T(*List->value);` ，这里 `List->value` 先运算，然后 `*List->value` 是对它的解引用，这样得到的就是指针指向的对象本身
然后 `T(*List->value)` 相当于利用了 T 的**拷贝构造函数** `T(const T&)`，把 `*list->value` 这个对象的内容**复制**到新分配的内存中。


### 1. 多态容器的定义与核心价值
* **本质**：一种特殊的**指针容器**，其模板类型通常为基类的指针（如 `List<Object*>`）。
* **核心能力**：利用 C++ 的**子类型替换原则**，使同一个容器可以同时存储不同派生类对象的指针（如在一个列表中同时放入 `Circle*`、`Square*` 和 `Triangle*`）。
* **动态绑定**：通过基类指针调用虚函数，实现“一个接口，多种实现”。

---

### 2. 对象切片 (Slicing) 问题
* **现象**：如果你尝试定义一个存储对象的容器（如 `List<Object>`）而非指针容器，并将派生类对象（`BigThing`）放入其中。
* **后果**：由于容器只为基类大小分配空间，派生类特有的数据成员和虚函数表会被“切掉”，仅保留基类部分。
* **形象比喻**：就像试图把一张巨大的风景画强行塞进一个小相框里，结果只能剪掉画的边缘，只留下中间的一小块。
* **结论**：实现多态容器**必须使用指针（或引用）**。

---

### 3. 深拷贝的终极挑战
* **困境**：当你尝试对多态容器进行深拷贝时，普通的 `new` 语句会失效。
    * 代码逻辑：`Object *copy = new Object(*original_ptr);`
    * **失败原因**：编译器在编译阶段只知道指针是 `Object*` 类型，因此它只会调用 `Object` 的拷贝构造函数。即使原对象其实是 `BigThing`，拷贝出来的也只是个残缺的基类对象。
* **技术瓶颈**：C++ 不支持“虚构造函数”，即无法直接在运行时动态决定创建哪种类型的对象。

---

### 4. 解决方案：Clone 模式 (虚拟构造函数)
* **命名构造函数惯用法 (Named Constructor Idiom)**：在基类中定义一个纯虚函数 `clone()`，由各派生类负责实现。
* **实现步骤**：
    1.  **基类定义**：声明 `virtual Object* clone() = 0;`。
    2.  **派生类实现**：
```cpp
Object* BigThing::clone() {
	return new BigThing(*this); // 派生类知道自己的真实类型
}
```
* **拷贝逻辑更新**：
    * 不再使用 `new Object`，而是调用 `Object *o = list->value->clone();`。
* **形象比喻**：容器不再自己去“克隆”包裹，而是向包裹下达指令：“按你自己的样子复制一个”。包裹本身知道自己的型号和内容，因此能完美复刻。

### 5. 内存管理与虚析构函数
* **所有权原则**：多态容器通常对其持有的对象拥有“所有权”，因此在析构时需要手动遍历并 `delete` 每一个对象指针。
* **虚析构函数的必要性**：
    * **基类必须声明虚析构函数**：`virtual ~Object() {}`。
    * 如果析构函数不是虚的，当执行 `delete obj_ptr`（基类指针）时，程序只会调用基类的析构函数，而不会调用派生类的析构函数，导致派生类特有的资源（如派生类内部又 new 的内存）无法释放。

### 知识点总结表

| 特性 | 对象容器 (List<T>) | 多态指针容器 (List<T*>) |
| :--- | :--- | :--- |
| **存储内容** | 对象的副本 | 对象的内存地址 |
| **支持多态** | 否（会发生对象切片） | **是**（保留派生类完整信息） |
| **深拷贝方式** | 自动调用拷贝构造函数 | 必须通过 **clone()** 虚函数 |
| **内存释放** | 自动释放 | 需手动 `delete` 并配合 **虚析构函数** |
