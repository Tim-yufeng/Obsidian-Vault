### 1. 处理运行时异常的动机
* **运行时异常**：程序运行过程中出现的非预期状况，如文件不存在、无效输入等。
* **部分函数 (Partial Functions)**：并非对所有输入都有意义的函数（如 $n!$ 不支持负数）。
* **传统手段的局限**：
    * **REQUIRES 子句**：只是注释，没有强制执行力。
    * **运行时检查**：需要显式判断输入，但接下来的处理逻辑往往很尴尬。

---

### 2. 处理非法输入的三大策略
1.  **“那是我的问题” (内部消化)**：
    * 尝试修复输入或返回“默认合理值”。
    * **比喻**：餐厅缺某种食材，厨师自作主张换成类似的，不告诉客人。
    * **局限**：某些操作没有默认值（如除以 0 无法定义）。
2.  **“我放弃了” (硬退出)**：
    * 使用 `assert()` 直接终止程序。
    * **局限**：不够友好，无法在退出前进行清理工作（如释放内存）。
3.  **“那是你的问题” (传球给调用者)**：
    * **返回错误码**：利用特殊的返回值（如 -1）表示失败。
    * **局限**：如果函数所有可能的返回值都有意义（如 `list_first` 可能返回任何整数），就没法编码错误码。
    * **可扩展性差**：每一层调用都要手动检查、手动传递，代码会变得臃肿且逻辑混乱。

---

### 3. 异常处理的概念与传播
* **核心逻辑**：将“正常业务逻辑”与“错误处理逻辑”分离，实现逻辑上的 **"Goto"** 切换。
* **异常传播 (Propagation)**：
    * 如果在当前函数中找不到处理器，异常会沿着**调用栈 (Call Stack)** 向上“漂浮”。
    * **传播路径**：当前函数 $\rightarrow$ 调用者 $\rightarrow$ 调用者的调用者 $\rightarrow$ `main()` $\rightarrow$ 操作系统（程序崩溃）。
    * **优势**：无需手动层层传递错误码，系统自动查找处理器。

### 4. C++ 异常语法详解
* **Throw (抛出)**：告知程序发生了异常。`throw n;` 抛出的可以是一个对象或基本类型。
* **Try 块**：受保护的代码区域。如果这里面的代码（或调用的函数）抛出异常，执行流会立即中断。
* **Catch 块 (Handler)**：响应异常。
    ```cpp
    try {
        // 正常业务
        if (n < 0) throw n; 
    } catch (int v) {
        // 针对 int 类型异常的处理
    }
    ```
* **重新抛出 (Re-throwing)**：在 `catch` 块中使用 `throw v;` 可以将捕获到的异常再次抛给上一层调用者。

---

### 5. 高级用法与执行流程
* **匹配规则**：
    * 异常对象会按 `catch` 块出现的**顺序**进行类型匹配。
    * **只有第一个**匹配成功的 `catch` 块会被执行。
* **默认处理器 (Catch-all)**：`catch (...)` 可以捕获任何类型的异常，通常放在最后作为保底方案。
* **处理后的流程**：如果异常被成功捕获并处理，程序将从该 `catch` 块**之后**的第一条语句继续执行。
* **异常类型**：可以使用基本类型（`int`, `double`），也可以使用自定义类型（`struct`, `class`）来携带更丰富的错误信息。

---

### 6. 规范与易错点 ==== 重要 ====
* **文档说明**：如果函数可能抛出异常，必须在 `EFFECTS` 规范中明确指出。
    * 例如：`// EFFECTS: returns n! if n>=0; throws int n otherwise.`
* **Catch 顺序**：必须先捕捉具体类型，再捕捉泛化类型（或 `...`）。
* **孤立的 Catch**：`catch` 块必须紧跟在 `try` 块之后，不能独立存在。
* **异常安全**：一旦异常发生，`try` 块内剩余的代码将**不再执行**。
