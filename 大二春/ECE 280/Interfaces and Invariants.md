### 1. 接口 (Interfaces)
* **核心定义**：接口是使用某种类型的“契约” (Contract)。它定义了对象能做什么，而不涉及如何去做。
* **ADTs 的本质**：对于调用者而言，一个抽象数据类型就是一个接口。只要满足契约，底层的具体实现可以自由替换。
* **C++ 实现问题**：
    * 之前的 `class` 定义（如 `IntSet`）将实现细节（`private` 数据成员）和接口定义混在了一个头文件中。
    * **后果**：即使只修改私有实现，所有包含该头文件的客户代码都必须重新编译，导致编译依赖过重。

---

### 2. 抽象基类与纯虚函数
* **纯虚函数 (Pure Virtual Function)**：
    * 语法：`virtual <返回类型> <函数名>(参数) = 0;`。
    * 含义：该函数在基类中没有定义，强制要求派生类必须实现它。
* **抽象类 (Abstract Class)**：
    * 包含==至少一个==纯虚函数的类。
    * **限制**：==抽象类不能创建实例（对象）==，但是可以创建它的指针或引用
    * **作用**：定义一个通用的接口规范，作为所有派生类的“祖先”。
```cpp
// IntSet is an abstract class
IntSet s;   // Not allowed!

IntSet &r = <something>;   // Allowed
IntSet *p;                 // Allowed
```
* **接口分离示例**：
    * 定义一个抽象基类 `IntSet`（仅含纯虚函数）。
    * 派生出 `UnsortedArrayIntSet` 或 `SortedArrayIntSet` 提供具体实现。

### 3. 不变式 (Invariants)
**不变式是程序在特定时刻必须满足的逻辑条件，分为两类：**

#### **(1) 结构不变式 (Structural Invariants)**
* 指向数据结构内部关系的逻辑。
* **例子**：在列表 ADT 中，`last` 指针必须始终指向列表的最后一个节点。

#### **(2) 表示不变式 (Representation Invariants / repOK)**
* 定义了具体表示（数据成员）与抽象值之间的映射规则。
* **IntSet 示例（有序数组版）**：
    1. `numElts` 必须在 `0` 到 `MAXELTS` 之间。
    2. 数组的前 `numElts` 个槽位存储有效数据。
    3. 数据必须**严格升序**排列且**无重复**。
* **作用**：它是成员函数执行前后的“信任基石”。函数开始时假设不变式成立，结束前必须修复并确保不变式依然成立。

### 4. 辅助函数与实现技巧
* **indexOf(v)**：
    * 在有序实现中，它应该利用**二分查找 (Binary Search)** 以达到 $O(\log N)$ 的效率。
    * 在无序实现中，通常使用**线性查找**。
* **逻辑复用**：许多公共接口（如 `insert`, `remove`, `query`）都可以基于私有的 `indexOf` 来实现，从而减少冗余代码。

---

### 5. 防御性编程与 repOK()
* **repOK() 方法**：
    * 一个私有的布尔函数，专门用于检查所有表示不变式是否被违反。
* **使用断言 (assert)**：
    * 在每个修改了数据的成员函数**返回前**加上 `assert(repOK());`。
    * 甚至可以在函数**进入时**也加上检查，确保调用前状态正常。
* **价值**：能够极早地捕捉由于逻辑漏洞导致的非法状态，防止 Bug 蔓延。

### 重点总结与易错点
* **抽象类不可实例化**：如果你试图 `IntSet s;` 而 `IntSet` 是抽象类，编译器会报错。
* **虚析构函数**：虽然本课件未详述，但当通过接口指针删除对象时，基类析构函数应设为 `virtual`（这是一个常见的进阶易错点）。
* **短路评估**：在实现 `insert` 的查重逻辑时，利用 `&&` 的特性先判断范围再访问数组，防止越界。
* **Invariant 的持久性**：不变式必须在**任何**公有方法执行完毕后都为真。
