## 抽象数据类型 (Abstract Data Types, ADTs) 深度笔记

### 1. 核心概念：什么是 ADT？
* **类型的本质**：一个类型由**值的集合**以及定义在这些值上的**操作集合**共同构成。
* **从 Struct 到 ADT**：
    * **Struct (具体实现)**：所有细节对用户公开。若修改底层（如将 C-string 改为 C++ string），所有调用处都得改，耦合度高。
    * **ADT (抽象描述)**：只描述“做什么”，隐藏“怎么做”。
* **两大支柱**：
    1.  **信息隐藏 (Information Hiding)**：用户不需要知道对象如何表示，也不需要知道操作如何实现。
    2.  **封装 (Encapsulation)**：将数据（属性）和操作（成员函数）定义在同一个实体（类）中。
* **比喻**：手机。类型是“便携电话”，操作是“开关机、拨号、发短信”。你不需要懂电路图（具体实现）就能使用它。

### 2. C++ 类 (Class) 基础
* **封装机制**：`class` 是实现 ADT 的主要手段。

    * **private (默认)**：仅类内部成员可见，用于隐藏实现细节。

    * 声明通常在 `.h` 文件，实现通常在 `.cpp` 文件。
    * 使用作用域运算符表示所属关系：`int anInt::get_value() { return v; }`。
* **this 指针**：成员函数内部隐含的指针，指向调用该函数的当前对象。

---

### 3. 代表性实例：整数集合 (IntSet)
* **需求**：一个无重复元素的整数集，支持插入、删除、查询、大小计算。
* **表示不变式 (Rep Invariant) **：
    * 这是表示层必须始终遵守的规则。
    * **无序版本规则**：元素存放在数组前 $N$ 个槽位；没有重复元素；`numElts` 始终等于当前元素个数。
    * 规则必须在任何成员函数执行前后都保持成立。

#### **具体操作实现逻辑**
* **indexOf(v)**：**私有辅助函数**。在数组中查找 $v$ 的下标。必须私有，因为它暴露了“底层使用数组存储”这一细节。
* **insert(v)**：先查 `indexOf`。若不存在且有空间，放在 `elts[numElts]` 并自增 `numElts`。
* **remove(v)**：查到下标（victim）后，将**最后一个元素覆盖到 hole（穴）**上，然后自减 `numElts`。
    * **技巧**：无序数组删除时，直接拿末尾填补空缺比整体左移效率更高。

---
### 4. 自动化初始化：构造函数 (Constructor)
* **痛点**：类对象声明时（如 `IntSet s;`），数据成员是随机值，这会违反“初始化时 size 为 0”的不变式。
* **构造函数特性**：
    * 名字与类名完全相同。
    * **没有返回值类型**。
    * 对象创建后自动调用的第一个函数。
* **初始化列表 (Initialization Syntax)**：
    * 推荐写法：`IntSet::IntSet() : numElts(0) {}`。
    * **易错点**：成员初始化顺序由它们在类中**声明的顺序**决定，而非初始化列表中的书写顺序。

---

### 5. 常量成员函数 (Const Member Functions)
* **语法**：在函数声明和定义的末尾加 `const`。如 `int size() const;`。
* **逻辑本质**：修改了隐含的 `this` 指针类型，使其指向一个**常量对象**。
* **作用**：==承诺该函数不会修改对象的任何数据成员==。
* **规则**：
    * ==`const` 对象**只能**调用 `const` 成员函数。==
    * ==`const` 成员函数内部调用其他成员函数时，被调用者也必须是 `const`。==
* **比喻**：就像给对象打了一层“只读”蜡，确保查询操作不会意外改变数据。

---

### 6. 效率优化：排序不变式 (Sorted Invariant)
* **改进**：维持数组元素**从小到大排序**。
* **性能对比**：
    | 操作 | 无序数组 (Unsorted) | 有序数组 (Sorted) |
    | :--- | :--- | :--- |
    | **query** | $O(N)$ (线性查找) | $O(\log N)$ (二分查找) |
    | **insert** | $O(N)$ (需先查重) | $O(N)$ (需挪动元素腾位) |
    | **remove** | $O(N)$ (查找耗时) | $O(N)$ (需“挤压”数组填坑) |

#### **有序版本的实现变化**
* **remove**：不能再拿最后一个填坑，必须将 hole 之后的所有元素**整体左移**。 * **insert**：从后往前比较，将比新元素大的项逐个右移，直到找到合适位置。 * **决策建议**：如果**查询频率远高于修改频率**，应使用有序版本；反之，无序版本代码更简单。

---

### 易错点汇总
* **私有与共有**：忘记将数据成员设为 `private`，或者忘记将 `get/set` 设为 `public`。
* **分号**：类定义的结尾 `};` 必须带分号。
* **传递方式**：类对象默认**按值传递**。若需修改对象，必须传**引用**（`IntSet&`）或**指针**。
* **不变式破坏**：在 `insert` 或 `remove` 后忘记更新 `numElts`，会导致 ADT 状态逻辑崩溃。
