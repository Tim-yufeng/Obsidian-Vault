一台计算机中内存的格局是这样的：

- 最下面是保留给操作系统的空间，我们不用管
- Program (Text) ，这个空间存储了所有待执行的命令，包括那些 ISA 命令和定义的函数，都是 CPU 可以直接理解的二级制格式
- Static Data，这个区域包含那些生存周期和整个程序一样长的变量，包括 Global Variable 和 Static local variable.
- Dynamic Data：顾名思义，就是动态分配的那部分空间
- Stack：函数调用过程中一些比较临时的数据

两类重要的指针，global pointer (gp) 和 stack pointer (sp)：
- gp 属于 Static Data区域，在其**中间部位**开始被激活（0x10008000），然后通过加减offset来访问该区域的不同位置
- sp 属于 Stack 区域，在栈的最顶部被激活，在280中我们学过，栈是从上往下生长的，最顶部其实就是栈底，这个指针会动态的调整，**始终指向栈顶元素**
- 注意这两个指针都直接占据了寄存器堆的各一个寄存器：
	- gp 占据 x3
	- sp 占据 x2

**Program Counter（PC）** 

首先记住，这玩意是一个 32-bit 的**寄存器**，位于 CPU，但是独立于寄存器堆，作用是**存储即将被CPU执行的命令的内存地址**
这些命令来自 Program (Text) 区域，有自己的地址，如果命令被label，那么label会直接代表命令的地址
和寄存器堆中的寄存器不一样，PC 是受时钟信号驱动的
这个时钟信号的频率，直接决定了命令执行的速度，也就是计算机的运行速度
每个指令占据 32-bit，因此 PC 执行完一条指令后通过地址 +4 来到下一条指令

![[Pasted image 20260521192506.png]]
`jal` 和 `jalr` 的区别就是，前者通过 label 来确定 PC 需要跳转的地址，后者则通过 已知地址+offset 的方式，这种方式更加灵活，理论上什么地方都能跳转（但这也带来了一定危险性）

前一个参数是 return address，作用是在跳转前，记录下跳转位置的下一条指令，方便完成跳转地点的所有操作后直接回来继续执行，所以我们看到它的值是 PC+4；此外，我们规定寄存器堆中的 x1 专门用来存储这个东西，因此 x1 也被称为 return address reg
这是跳转过去的情况，如果要跳转回来，一般只用 `jalr`，因为它能直接用上我们之前记录在 x1 中的回归的地址，因为没有要 offset 的，并且也没必要再存储 return address, 所以跳转回来的命令一般固定就是 `jalr x0, 0(x1)`

在上一节我们说过，除去那些有特殊功能的寄存器，两类寄存器：temporary registers 和 saved registers 是可以作为普通用途的，但是他们在使用传统上也有区别。
temporary registers 是用来存储临时的、不重要的值的寄存器，可以随时拿来使用，不用考虑其残留值要不要保存的问题
因此如果你在一次函数调用之前，用 temp 寄存器保存了一个数值，这个函数结束之后，理论上你已经无法确定该寄存器的状态了（鬼知道它又被塞了什么进去）
但是 saved registers 在每次函数调用前，必须先把残留值保存进 stack，在函数调用结束后，再把原本的值还原回去

`lb` 和 `lbu` 都是 load byte 的意思，前者针对 signed（按照最高位来补充前面的bit)，后者是 unsigned（无脑补0）
和 `lw` 加载一个 word 的地址不同，`lb` 只加载一个 byte 的地址，因此它的offset可以是任何整数，不像 `lw` 只能是4的倍数

类似的，我们还有 `lh` ：load half，这是把两个 byte 作为一个 half 进行加载，地址是这两个 byte 较小的那个地址，它的offset必须是偶数
