算法快不快，不该看某一次运行显示的秒数。编译器、机器型号、当时的 CPU 负载都会改变这个数。渐近分析把问法换掉：当输入规模 $n$ 变大时，运行时间 $T(n)$ 按什么趋势增长。

## 输入规模与三种情况

“规模”要先说清楚：数组看元素个数，图看顶点数 $V$ 和边数 $E$。数组求和这类算法，同样规模下不管数据长什么样耗时都差不多；linear search 就不一样，key 的位置直接决定要比几次。所以要看三种情况。

- **best case**：同规模里步数最少的输入，比如 key 恰好在第一个位置。
- **worst case**：同规模里步数最多的输入，比如 key 不在数组里，或者刚好在最后一个。
- **average case**：按某个输入分布取期望得到的步数，不等于“随便挑一个输入”。

这里有个容易说错的点：best case 并不是“$n=1$ 的那个输入”。分析时规模 $n$ 是固定的，==best case 指的是同规模输入中最便宜的那一个。==

实际最常用 worst case，因为它给出可靠的界，也通常更好算。average case 更公平，但需要知道输入分布，或者依赖算法自身的随机性。

选哪个取决于场景：quicksort 平时很快，而 QoS 这类服务更在乎最坏情况扛不扛得住。

## 为什么忽略常数，只看大的 $n$

两个原则：忽略常数因子；只关心 $n$ 很大时的表现。常数不重要，是因为它们跟着架构和编译器走，而且 $n$ 一大，增长趋势总会压过常数。

课件里的三算法对比很典型：$T_A(n)=2^n$、$T_B(n)=1024n$、$T_C(n)=4096n$。$n$ 很小时 $2^n$ 还追不上任何一条直线，$A$ 反而是最快的；但过了 $n>13$、$n>15$ 两处交叉点，$B$ 和 $C$ 就反过来赢了。换成任意固定常数 $T_X(n)=cn$，$2^n$ 迟早也会超过它。

<span class="green">常数只能把交叉点往后推，不能把它取消掉。</span>

## Big-Oh：一个最终的上界

<span class="red">Big-Oh 说的是一个最终上界：输入规模足够大以后，运行时间不会超过某个参照函数的常数倍。</span>

写成式子就是：存在正常数 $c$ 和 $n_0$，使得

$$
T(n)\le cf(n),\qquad \forall n>n_0 .
$$

$c$ 用来吸收实现细节，$n_0$ 用来跳过小规模时的波动，两者都不必取最小值。

图上蓝线是 $2f(n)$（即 $c=2$），它从 $n_0$ 右侧开始一直盖住绿线 $T(n)$，这就是定义在图像上的样子；$n_0$ 左边发生过什么并不重要。

严格说应该写 $T(n)\in O(f(n))$，平时写成 $T(n)=O(f(n))$ 只是方便。这个等号不能反着用：$2n=O(n^2)$ 成立，$n^2=O(2n)$ 不成立。

### 怎么快速算 Big-Oh

口诀两步：找增长最快的一项，再把系数丢掉。对最高次项系数为正的多项式

$$
T(n)=a_mn^m+a_{m-1}n^{m-1}+\cdots+a_0,
$$

就有 $T(n)=O(n^m)$。另一个常用充分条件是

$$
\lim_{n\to\infty}\frac{f(n)}{g(n)}=c<\infty
\quad\Longrightarrow\quad
f(n)=O(g(n)).
$$

它适合快速确认主导项，不过定义本身才是根本依据。Big-Oh 还能直接做运算：

$$
f_1+f_2=O(\max\{g_1,g_2\}),\qquad f_1f_2=O(g_1g_2).
$$

相加取较慢的一方，相乘则两边相乘；另外常数倍不影响结果，这个界还可以传递。这解释了为什么顺序执行的两段代码由较慢的一段主导，而嵌套的代价常常相乘。

指数里多出来的常数同理：$2^{n+10}=1024\cdot 2^n$ 只是把常数提出来，所以 $2^{n+10}=O(2^n)$。

上界可以很松：$T(n)=3n^2$ 说成 $O(n^3)$ 并没错，但我们要尽量贴近的写法。所以 $f(n)=0.5n+n\log_2 n$ 应该报 $O(n\log n)$，而不是 $O(n^2)$。

### 常见增长率

$$
1,\ \log n,\ \sqrt n,\ n,\ n\log n,\ n^2,\ n^3,\ n^k,\ a^n,\ n!.
$$

课件默认 $\log n$ 指 $\log_2 n$。要记住的关键比较是：固定次数的对数被线性压住，固定次数的多项式被指数压住，

$$
\log^k n=O(n),\qquad n^k=O(2^n)\qquad(k\ge1).
$$

反过来说，$3^n=O(2^n)$ 不成立——底数不同的指数不能互相约束；而 $\log_2 n$ 与 $\log_3 n$ 只差一个换底常数，所以 $\log_2 n=O(\log_3 n)$ 成立。

## Big-Omega 与 Theta

Big-Omega 是方向相反的下界：$T(n)=\Omega(g(n))$ 表示存在 $c>0$ 和 $n_0$，当 $n>n_0$ 时

$$
T(n)\ge cg(n).
$$

它的运算规则和 Big-Oh 一一对应。我们通常希望下界尽量大。

当同一个 $g(n)$ 既是上界又是下界，就得到 Theta：

$$
c_1g(n)\le T(n)\le c_2g(n),\qquad \forall n>n_0 .
$$

这时 $g(n)$ 才真正刻画了增长速度，比如 $T(n)=c_1n^2+c_2n$ 有 $\Theta(n^2)$。

![[Pasted image 20260916130257-01.png]]

图中 $f(n)$ 被 $c_1g(n)$ 和 $c_2g(n)$ 一上一下夹住，所以 $\Theta$ 是对称的：$f(n)=\Theta(g(n))$ 也意味着 $g(n)=\Theta(f(n))$。

顺便说，实践中大家偏爱接近线性的算法；做到 sublinear（例如 $O(\log n)$）很难，但并非不可能，binary search 就是一个。

## 从程序得到复杂度

先找会重复执行的基本操作，再把控制结构翻译成次数。

- 原子语句（赋值、一次加法）是 $\Theta(1)$。加法算不算原子操作？概念上算，真实机器上会复杂一些。
- 分支（if-else、switch）的代价，是最贵的条件判断加上最贵的那个分支的代价，做 worst case 时不能假装昂贵的分支不走。
- 子程序调用的代价就是子程序自身的代价。
- 循环的代价要看实际迭代总次数，而不是数了几层。

循环是唯一需要动手算的。单层循环老老实实跑满 $n$ 次，就是 $\Theta(n)$；内层次数随外层变化时，则要把每轮的工作量加起来：

```cpp
sum = 0;
for (i = 1; i <= n; i++)
    for (j = 1; j <= i; j++)
        sum++;
```

第 $i$ 轮做 $i$ 次，总数是

$$
1+2+\cdots+n=\frac{n(n+1)}2=\Theta(n^2).
$$

外层翻倍、内层每次整扫一遍，则是 $\Theta(n\log n)$：外层只跑 $\log n$ 轮，每轮扫 $n$ 个。

```cpp
sum = 0;
for (i = 1; i <= n; i *= 2)
    for (j = 1; j <= n; j++)
        sum++;
```

如果内层长度跟着外层翻倍，而不是固定为 $n$，各轮工作量是 $1,2,4,\dots$，直到 $n$：

```cpp
sum = 0;
for (i = 1; i <= n; i *= 2)
    for (j = 1; j <= i; j++)
        sum++;
```

总和是 $1+2+4+\cdots+2^{\log n}\approx 2n-1$，整体是 $\Theta(n)$。

<span class="green">看到两层 for 就写成线性对数级是常见的误判，真正决定复杂度的是所有执行次数的总和。</span>

### 折半和递归都先写递推式

binary search 每轮把待查区间砍掉一半，本层只做常数工作：

```cpp
int binarySearch(const int a[], int n, int key) {
    int left = 0;
    int right = n - 1;

    while (left <= right) {
        int mid = (left + right) / 2;
        if (a[mid] == key) return mid;
        if (a[mid] < key) left = mid + 1;
        else right = mid - 1;
    }
    return -1;
}
```

区间长度从 $n$ 变成 $n/2,n/4,\dots,1$，所以

$$
T(n)=T(n/2)+\Theta(1)=\Theta(\log n).
$$

而朴素的 fibonacci 递归两个分支都会真的执行：

```cpp
int fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);
}
```

调用树每层几乎翻倍，所以是 $O(2^n)$。对比之下 merge sort 的递推式是

$$
T(n)=2T(n/2)+O(n)=O(n\log n),
$$

它正属于 Master theorem 中 $a=b^d$ 的情形（课件提示 Master theorem 来自 MATH2030J）。

## 多参数与空间换时间

有些问题没法只用一个 $n$ 描述。比如统计一张 $P$ 个像素、$C=256$ 种取值的图片：初始化 $\Theta(C)$、扫描像素 $\Theta(P)$、再把计数排序 $\Theta(C\log C)$，合起来

$$
\Theta(P+C\log C).
$$

保留两个参数才能看出瓶颈跟着谁变，分析图算法时同时看顶点数和边数也是这个道理。

另一个常用原则是时间和空间可以互换。求 $n!$ 时，一边乘一边算只要 $\Theta(1)$ 额外空间、$\Theta(n)$ 时间；把结果预先存进数组，单次查询变成 $\Theta(1)$，代价是表本身占 $\Theta(n)$ 空间。以后看到“更快”的算法，可以顺手问一句：它是把工作提前做了，还是换成了额外存储？
