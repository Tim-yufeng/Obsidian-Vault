## Prompt 1 — Stage 1: Corpus Audit

你当前位于我的个人笔记风格学习仓库 `NoteStyleCorpus`。

这个仓库不是我的真实 Obsidian Vault，而是我人工筛选后专门提供给你研究个人 note-taking style 的学习语料库。`courses/` 中出现的内容都允许你分析；仓库外的任何笔记都不属于学习集合。

当前任务仅仅是 corpus audit。不要开始总结我的个人风格，不要创建最终 Skill，也不要修改 `courses/` 中任何源文件。

请扫描 `courses/`，建立这个语料库的结构性认识。

每门课程可能包含：

- `slides/`：课程原始课件，均为 PDF；
    
- `notes/`：我本人过去编写的 Markdown 或 LaTeX 笔记；
    
- 与笔记同名或对应的 `.pdf`：该笔记最终渲染后的视觉版本。
    

注意：

1. 有些课程全部笔记位于一个 Markdown/TeX 文件中，不同 chapter 通过明确的 heading 划分。
    
2. 有些课程每个 chapter 是单独的笔记文件。
    
3. 课件同样可能是一整个课程一个 PDF，也可能每章一个 PDF，但 chapter boundaries 是明确的。
    
4. Markdown/TeX 源文件是语言、结构和原始写法的主要依据；rendered PDF 用于理解截图、视觉结构和最终排版。
    
5. LaTeX 笔记属于较早期作品。它们可以是非常有价值的语言、解释深度、思考方式、比喻和幽默样本，但其 LaTeX 排版实现不是未来 Obsidian 输出格式的样本。
    
6. 某些笔记中可能存在指向其他个人思考文档的链接。被链接文档被我有意排除在本 corpus 外。不要追踪、寻找、恢复或推测这些文档。
    
7. 历史笔记不是完美 ground truth。笔误、赶时间、偷懒、省略、偶发的不一致都可能存在。不要因为某种行为出现过一次就认定它是偏好。
    
8. 不要按完整程度判断价值。一个只覆盖前几个 chapter 的笔记仍可能是非常优秀的风格样本。
    

请创建：

`system/corpus/CORPUS_INDEX.md`

对每门课程和主要笔记标注：

- 文件/章节结构；
    
- source format；
    
- 是否有 rendered companion；
    
- probable note mode：
    
    - slide-following
        
    - question-driven
        
    - review/exam-oriented
        
    - reference
        
    - mixed
        
- probable learning intent：
    
    - deep
        
    - balanced
        
    - exam
        
    - reference
        
    - mixed/uncertain
        
- style-learning value：
    
    - Tier A: strong exemplar candidate
        
    - Tier B: useful with caution
        
    - Tier C: do not infer general style from this material
        
- 判断理由；
    
- 任何明显的 noise/rushed-section 风险。
    

同时创建：

`system/corpus/SOURCE_MAP.md`

尝试建立 slide source 与 note section 的 correspondence。

优先利用：

- chapter title；
    
- Markdown/LaTeX heading；
    
- slide chapter heading；
    
- terminology overlap；
    
- 内容顺序。
    

无需人工精确标注每一页。使用：

- high confidence
    
- medium confidence
    
- low confidence
    

表示 mapping 可信度。

对于 Tier-A 候选，应尽量建立可靠 mapping；低可信关系不要伪装成确定事实。

完成后只汇报：

1. corpus 总体结构；
    
2. 你认为最值得我人工检查的分类；
    
3. 你最不确定的 mapping。
    

不要进行 Style Guide 编写。

## Prompt 2 — Stage 2: Exemplar Selection

基于我已经检查/修正过的：

`system/corpus/CORPUS_INDEX.md`  
`system/corpus/SOURCE_MAP.md`

现在开始 exemplar selection。

仍然不要编写最终 STYLE_GUIDE。

请从整个 corpus 中选取大约 15–30 个真正具有代表性的局部 exemplar，而不是简单选择完整文件。

优先覆盖：

- slide-following + deep
    
- slide-following + balanced
    
- slide-following + exam-oriented
    
- question-driven + deep
    
- review/reference
    
- formal source → intuitive personal explanation
    
- mathematical reasoning/derivation
    
- concept connection
    
- screenshot use
    
- concise treatment of trivial content
    
- unusually successful analogy/joke/playful remark
    
- Chinese explanation with English technical terminology
    

每个 exemplar 在：

`system/style/EXEMPLAR_INDEX.md`

中记录：

- course
    
- note source path
    
- exact heading/section
    
- corresponding slide PDF + chapter/page range when confidently identifiable
    
- note mode
    
- learning intent
    
- why this exemplar is valuable
    
- what exactly should be learned from it
    
- what should NOT be generalized from it
    

重要原则：

A historical example is evidence, not automatically a rule.

优先级为：

1. 后续我明确给出的 correction；
    
2. 多个 Tier-A exemplar 中稳定重复的模式；
    
3. 单个非常高质量 exemplar 中具有明显认知价值的模式；
    
4. 普通历史行为；
    
5. rushed/noisy behavior —— 最低，不应模仿。
    

特别注意：

- 不要因为一个笔记很长就认为它更重要。
    
- 不要把笔误、懒惰、省略和输入法切换产生的不一致当作 style。
    
- 不要为了课程覆盖均匀而加入差 exemplar。
    
- LaTeX exemplar 可以用于认知风格、解释方式、个人语气和 analogy，但不能作为未来 Markdown/Obsidian 排版规范。
    
- question-driven notes 必须标明其 mode，避免污染普通 slide-following note 的组织逻辑。
    

完成后不要继续进行 Style Guide。让我先检查 exemplar selection。

## Prompt 3 — Stage 3: Learn the Note-Taking Policy

现在 `EXEMPLAR_INDEX.md` 已经经过我的检查，可以开始正式提炼我的 note-taking policy。

请结合：

`system/corpus/CORPUS_INDEX.md`  
`system/corpus/SOURCE_MAP.md`  
`system/style/EXEMPLAR_INDEX.md`

并重新读取 exemplar 所指向的实际 source slides、原始 `.md/.tex` 和必要的 rendered PDF。

创建：

`system/style/STYLE_GUIDE.md`  
`system/style/SCREENSHOT_POLICY.md`

目标不是模仿表面文风，而是学习：

source material + learning intent  
→ information selection  
→ conceptual processing  
→ explanation  
→ screenshot decision  
→ final note

STYLE_GUIDE 至少应区分四层：

1. Stable cognitive style
    
    - 我如何理解新概念；
        
    - 我如何从 formal statement 转向 intuitive understanding；
        
    - 我什么时候追问 why；
        
    - 我如何建立前后知识连接；
        
    - 什么内容值得展开，什么内容一句话即可。
        
2. Note mode
    
    - slide-following
        
    - question-driven
        
    - review/reference
        
3. Learning intent
    
    - deep
        
    - balanced
        
    - exam
        
    - reference
        
4. Surface realization
    
    - headings
        
    - paragraph/list balance
        
    - formulas
        
    - terminology
        
    - screenshots
        
    - tone
        
    - analogy/jokes
        
    - Markdown conventions
        

必须遵守这些人为确定的规则：

### Terminology

主体解释语言是中文。

对于课程中反复出现的正式专业术语，优先保留英文，因为我的 slides、lecture、homework 和 exam 环境主要使用英文。

专业术语第一次需要正式引入时，优先采用类似：

`finite state machine (FSM)`

之后使用：

`FSM`

中文翻译是可选辅助，而不是必须格式。

不要从旧笔记中因输入法切换产生的随机中英文选择学习随机性。

不要为了显得“中英混合”而刻意插入英文；英文应主要用于真正的 technical vocabulary。

### Playfulness

我的笔记允许自然出现：

- personal joke
    
- unusual analogy
    
- casual aside
    
- slightly playful wording
    
- imaginative mental model
    

但这是 permission, not quota。

不要为了“像我”而强行制造笑话、吐槽、反问或比喻。如果它不能自然帮助理解，就不要出现。

### Noise resistance

Historical notes are imperfect observations of my preferred style, not a perfect specification.

Do not imitate:

- typos
    
- visibly rushed writing
    
- accidental omissions
    
- random terminology switching
    
- inconsistent formatting
    
- incomplete sentences caused only by laziness
    
- isolated quirks unsupported by stronger examples
    

When examples conflict, prefer:

1. explicit corrections from me
    
2. Tier-A exemplars
    
3. repeated patterns across good exemplars
    
4. isolated examples
    

### Linked reflection notes

If an old note links to a separate personal reflection document that is not included in the corpus:

- do not follow it;
    
- do not reconstruct it;
    
- do not infer its content;
    
- do not conclude that the AI should autonomously create such documents.
    

Independent intellectual exploration remains my task, not an automatically outsourced note-generation task.

SCREENSHOT_POLICY 应从 paired source-note examples 中分析我什么时候会选择截图，尤其包括但不限于：

- visual structure itself is conceptually valuable;
    
- formal theorem/definition is long and rigorous while my own prose supplies intuitive interpretation;
    
- a slide is already an unusually efficient dense summary;
    
- I want to preserve how the lecture formally/visually presented something and then explain my own understanding;
    
- retranscribing substantial slide content adds work without improving understanding.
    

也应明确什么时候不截图。

最终写成“另一个没有读过我历史笔记的 agent 也能够执行”的操作规范，而不是文学性的文风评价。

完成以后不要创建 Skill。先让我检查两个 policy 文件。
